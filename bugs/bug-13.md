# BUG-13: JSON null POST-ийн дараа сервер HTTP хариу өгөхөө болино

Орчин: Уншлагын жагсаалт v2.0; Node.js v20.19.2; Chromium 154.0.8037.57 (headless); Debian GNU/Linux 13.6 x86_64; 2026-10-20; Asia/Ulaanbaatar. UI viewport 1440 × 1000, өөрөөр заагаагүй бол.

Урьдчилсан нөхцөл: Багшийн өөрчлөгдөөгүй app.js файлыг репозиторийн үндсэн хавтаст байрлуулсан. Өөрийн өмнөх app процессыг зогсоож, `node app.js`-ийг шинээр асаасан; анхны «Тунгалаг Тамир», «Clean Code», «The Pragmatic Programmer» гэсэн 3 номтой. UI-д `http://localhost:3000`-г нээнэ. Хэрэв Node-ийн олон хувилбартай бол `node -v` нь v20.19.2 гэдгийг эхлээд батална.

## Дахин гаргах алхам

1. Шинэ app.js процесс анхны 3 номтой, үндсэн хуудас ажиллаж байгааг батална.
2. JSON root утга `null` бүхий хадгалсан request-ийг доорх локал curl командаар илгээнэ.
3. Хүсэлтийн үр дүнг харж, үндсэн хуудсыг браузераар дахин нээнэ.
4. Өөрийн app процессыг шинээр асаах хүртэл хуудас нээгдэх эсэхийг шалгана.

Давтах команд (зөвхөн локал тестийн аппад; хэрэглэгчийн заавраас хойш бид дахин ажиллуулаагүй):

```sh
curl -sS --max-time 10 -i -X POST http://localhost:3000/api/books \
  -H 'Content-Type: application/json' \
  --data-binary @evidence/bug-13-request.json
```

Хүлээгдэж байсан: `null` нь шаардлагатай номын талбаруудгүй тул ойлгомжтой client/validation алдаагаар няцаагдана; сервер бусад хүсэлтэд хариулах чадвараа хадгална. Oracle: талбарууд заавал бөглөгдөх дүрэм болон буруу хэрэглэгчийн оролтоос бүх үйлчилгээ унтрах ёсгүй гэсэн эрүүл ухаан.

Бодит үр дүн: POST нь HTTP response/status мөргүйгээр тасарч curl exit 52, «Empty reply from server» болсон. Дараагийн GET curl exit 7, браузер reload ERR_CONNECTION_REFUSED; дараагийн шинэ app процессоор л хэвийн болсон. Session-д 16:01:30, 16:04:26, 16:07:19 цагт шинэ процессоос гурван удаа ижил ажиглагдсан. Эх код/дотоод root cause-ийг шалгаагүй; server-unreachable зан төлөв л баталсан. Хэрэглэгчийн API хоригийн дараа дахин туршаагүй.

Ноцтой байдал: **Critical — нэг буруу бүтэцтэй хүсэлтийн дараа тестийн үйлчилгээ бүхэлдээ хүрэх боломжгүй болж, сэргээхэд app restart шаардсан. Энэ нь зөвхөн талбар буруу хадгалах BUG-09-өөс ялгаатай үйлчилгээний тасалдал.**
